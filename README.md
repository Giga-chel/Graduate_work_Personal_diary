# Личный дневник

Учебный проект: веб-приложение «Личный дневник» на Django (шаблоны, Bootstrap 5).
Пользователь ведёт записи и видит только свои; модератор может просматривать
и редактировать все записи. Запускается через Docker Compose.

## Возможности
- Регистрация и аутентификация (Django auth)
- CRUD записей: создание, просмотр, редактирование, удаление
- Список записей с пагинацией и поиском по заголовку и содержимому
- Разграничение прав доступа на основе групп и разрешений Django
- Полностью разворачивается в Docker

## Технологии
Python 3.14, Django 6.1, PostgreSQL 16, Bootstrap 5, Gunicorn, Docker Compose

## Запуск
1. Клонировать репозиторий:
   ```
   git clone https://github.com/<твой-логин>/<имя-репо>.git
   ```
2. Создать файл `.env` по образцу `.env.template`
3. Поднять контейнеры:
   ```
   docker compose up -d --build
   ```
   При старте автоматически выполняются миграции, collectstatic и init_roles
   (создание групп «Модераторы» и «Пользователи» с правами)
4. Создать суперпользователя:
   ```
   docker compose exec web python manage.py createsuperuser
   ```
5. Открыть http://localhost:8000

## Переменные окружения
| Переменная | Описание |
|---|---|
| SECRET_KEY | секретный ключ Django |
| DEBUG | режим отладки (в бою — False) |
| POSTGRES_DB / POSTGRES_USER / POSTGRES_PASSWORD | параметры базы |
| DB_HOST / DB_PORT | хост и порт БД (в Docker — db:5432) |

## Права доступа
| Роль | Возможности |
|---|---|
| Аноним | только вход и регистрация |
| Пользователь | CRUD своих записей, поиск |
| Модератор (группа «Модераторы») | просмотр всех записей, редактирование и удаление любых |
| Суперюзер | всё + админка /admin |

Механика: право `view_all_entries` (кастомное, из `Meta` модели) открывает просмотр
всех записей, `change_entry` (встроенное) — редактирование и удаление. Доступ
разграничен во вьюхах (`LoginRequiredMixin`, фильтрация queryset по правам),
шаблоны лишь отражают права в интерфейсе.

### Как проверить
1. Аноним → главная перенаправляет на вход
2. Регистрация → создание записей → видны только свои
3. Второй аккаунт → чужая запись по прямой ссылке → 404
4. Модератор → видит и правит все записи
5. Суперюзер → /admin
